OVERVIEW

项目定位

cetz-demos 是一个演示与教学性质的矢量图集项目。它以 Typst（排版与编译引擎）和 CeTZ（基于 TikZ 思想的 Typst 绘图库）为核心，用纯代码方式描述十二种不同领域的科学与工程图表， 并通过 Python 渲染脚本完成批量编译与质量校验。

「文档原生」是该项目的核心理念：每张图都是一段 Typst 代码， 可直接嵌入 Typst 文档、可被版本控制、可按任意分辨率重渲。 输出的透明 PNG 则便于在幻灯片、网页与设计稿中直接复用。

SYSTEM CONTEXT

系统上下文

项目处于「开发者 → 图集项目 → 外部编译工具」的简单三层结构中。 核心外部依赖只有两个：Typst 编译器（负责将 .typ 源码渲染为 PNG） 与 CeTZ 包（Typst 生态中的绘图库，通过 preview 渠道引入）。

系统上下文图

上下文解读：本项目自身不包含任何运行时服务或后端进程， 它是一个源码+脚本+产物三位一体的静态图集项目。开发者通过 uv run python scripts/render.py 触发构建， 脚本调用系统中安装的 Typst 编译器，后者在编译过程中自动从 Typst 包仓库拉取 CeTZ 0.5.2（首次运行时）。

编译完成后，脚本使用 Pillow 对每张输出 PNG 进行三维质量校验， 通过则保留在 out/ 目录中供下游使用。 下游消费者（幻灯片、网页、论文）只依赖最终的 PNG 文件，与构建过程完全解耦。

RENDER PIPELINE

渲染流水线

一次完整的渲染过程分为五个阶段，从目录校验开始，到最终的像素级质检结束。 每个阶段都有明确的输入、输出与失败条件，确保构建的可预测性。

渲染流水线（动画演示）

流水线解读：渲染脚本启动后，首先读取 catalog.json 并校验场景数量与唯一性——这是防止目录破损或重复的第一道防线。 接着检查 Typst 编译器是否在 PATH 中可用，不存在则直接终止。

主循环以目录中定义的场景顺序逐次编译：每个 .typ 文件通过 typst compile --ppi 190 命令被独立渲染为同名 PNG。 编译完成后，脚本用 Pillow 打开图像并转换为 RGBA 模式， 从透明度、可见度、色彩丰富度三个维度统计像素分布， 任一维度不达标即中断并报错。

全部通过后，脚本向标准输出打印一行 JSON 格式的统计报告， 包含场景名、尺寸、透明率、可见率与彩色像素数，便于 CI 系统解析。

QUALITY GATE

质量校验层

与「只要编译成功就认为通过」的常规做法不同，本项目引入了 像素级三维质检，确保输出图像不是空白、不是纯黑、 也不是因渲染异常产生的单色图。

三维校验模型

校验维度详解：第一维是透明度——统计 Alpha 通道值为 0 的像素占比， 低于 5% 说明背景填充可能失效或尺寸计算异常。第二维是可见度—— Alpha 值大于 16 的像素占比低于 2.5%，意味着图像几乎全透明，可能是绘制内容完全超出画布。

第三维是色彩丰富度——统计 R、G、B 三通道最大最小值之差大于 24 （即具有可感知色差）的像素总数，低于 1000 说明图像可能是单色调的线框或灰度图， 与本项目「彩色科学图示」的定位不符。三维同时通过，才算一次合格的渲染。

MAIN WALKTHROUGH

主走查：九点圆渲染

以 geometric_proof（九点圆几何证明图）为例， 逐步追踪一次完整的「从源码到出图」端到端流程。 九点圆是 CeTZ 几何绘图能力的典型示例，涉及构造点、连线、圆填充与文字标注。

1

读取目录与场景解析

脚本启动后加载 catalog.json，从中提取 12 个场景 ID， 包括 geometric_proof。校验数量与唯一性后， 在 sources/ 目录下定位到同名 .typ 源文件。

2

调用 Typst 编译

脚本通过子进程执行 typst compile --ppi 190 sources/geometric_proof.typ out/geometric_proof-transparent.png。 Typst 解析源码：导入 CeTZ 0.5.2、设置页面自适应尺寸与透明填充、 在 canvas 中执行 CeTZ 绘图命令（三个顶点、三条中点连线、九点位圆、标注文字）。

3

生成透明 PNG 输出

Typst 将矢量绘图栅格化为 190 PPI 的 RGBA 位图。由于页面 fill: none， 背景区域 Alpha 为 0；三角形、圆、文字等图形元素则以不透明像素写入。 输出写入 out/ 目录。

4

三维像素校验

Pillow 读取 PNG 并转为 RGBA。先做 Alpha 直方图判断透明/可见比例， 再枚举所有像素颜色统计彩色像素数。九点圆包含粉色/青色/黄色的顶点与高线、 蓝色的圆填充，彩色像素数远高于 1000 阈值，校验通过。

5

输出统计并进入下一循环

脚本向 stdout 打印一行 JSON，记录该场景的尺寸与各项比例。 随后以同样的流程处理剩余 11 个场景，全部通过后进程以 0 状态码退出。 若任一场景失败，进程立即以非零状态码终止，错误信息中附带场景名与各维度数值。
